CleanTech MRV Engine: Temporal Matching Logic

To calculate the temporal matching performance in strict 15-minute intervals, the database must aggregate the raw telemetry data using a specific set of mathematical formulas.

Here is the exact logic MRV Engine will use to calculate production, consumption, and the resulting carbon deficit.

1. Total Consumption & Generation (15-Min Window)

First, the system sums all individual smart meter readings ($i$) recorded within that specific 15-minute timeframe.

$$E_{consumed} = \sum_{i=1}^{n} C_i$$
$$E_{generated} = \sum_{i=1}^{n} G_i$$

(Where $C_i$ represents each industrial consumption reading, $G_i$ represents each renewable generation reading, and $E$ is total Energy in kWh).

2. The Temporal Match (Actual Green Energy Used)

A facility cannot claim to use more green energy than it actually consumed during that exact window. The matched energy is simply the lower value between what was generated and what was consumed.

$$E_{matched} = \min(E_{generated}, E_{consumed})$$

3. Temporal Match Score (%)

This calculates the percentage of the facility's power that was genuinely green during that interval.

$$Score_{green} = \left( \frac{E_{matched}}{E_{consumed}} \right) \times 100$$

4. Carbon Deficit (%)

This formula powers the visual carbon deficit heatmap by pinpointing the exact intervals where clean generation fell short.

$$Deficit_{carbon} = 100 - Score_{green}$$

Concrete Example:

If an industrial grid consumes 500 kWh ($E_{consumed}$) between 2:00 PM and 2:15 PM, but the solar array only generates 300 kWh ($E_{generated}$) due to cloud cover:

  • ➔ Matched Energy   = $\min(300, 500) = 300$ kWh.
  • ➔ Green Score   = $(300 / 500) \times 100 = 60\%$.
  • ➔ Carbon Deficit   = $100 - 60 = 40\%$.
API will instantly flag this 40% deficit, proving that the facility was forced to rely on dirty grid backup for the remaining 200 kWh.
